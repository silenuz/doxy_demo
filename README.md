Description:
------------
Simple proof of concept for using cmake with a python script to generate godot docs from doxygen generated XML

It uses the [Godot cpp template](https://github.com/godotengine/godot-cpp-template) as the base extension project.

Two classes have been added to the src directory, Summator and TrafficLight from Godotcon 2024.  The header files for these classes have been
heavily commented, it is from these comments that the documentation is generated.  

First cmake has to be configured, this will create a Doxygen configuration file in the cmake build directory.  
The options for Doxygen are configured in the [doxy_docs.cmake](/cmake/doxy_docs.cmake) file.  

Configure:
```cmake -S . -B cmake-build -G Ninja```

When you build the project with the target of doc_doxygen, Doxygen is run, and it parses the source code from the input folders.
After parsing the source code it writes it's output to the docs directory in the cmake build directory, under a subdirectory
named for the content type, for example xml.
When the build is finished cmake calls the python script [doxy_to_godot](cmake/doxy_to_godot.py) to parse the XML 
generated by Doxygen to produce Godot class documentation from it.

Build Docs:
```cmake --build cmake-build --target doc_doxygen```

Now there should be a new class documentation file for each of the demo classes in the doc_classes directory.

You can then build the project

```cmake --build cmake-build```

If you open the demo directory in the godot editor and open the example.gd, you should be able to hover over either of the constructors to 
see the documentation for that class.

Notes:
------
There are multiple predefined aliases for Doxygen in the [doxy_docs.cmake](/cmake/doxy_docs.cmake) file.  These aliases 
can be used to insert Godot specific elements into the Doxygen XML output that will be ignored by other document 
generators like Breathe that work with the Doxygen XML output.  This output is also ignored when producing html, latex, 
or man pages documentation.

The simplest of these aliases is the class linker.  

Here's part of [TrafficLight.h](/src/traffic_light.h) showing the class linker ```@glnk{Class}```
```
* The class <u>must inherit</u> from a Godot built in class (like @glnk{Object}, @glnk{Node}, @glnk{Sprite2D}, or @glnk{Resource}).
* Godot does not support multiple inheritance for GDExtension classes.
```
